一句话总评：英伟达今天开源了一套「给代理上锁」的软件，但锁要用它的芯片才转得动。

2026 年 9 月 28 日（当地时间周一），英伟达发布 Open Agent Safety Platform（开放智能体安全平台），由两半组成：OpenShell——开源（Apache 2.0）的安全运行时，跑在 CPU 上，把「代理能碰什么」写成可验证的策略并在代理进程之外强制执行；Sentry——运行在 BlueField-4 DPU 上的带外硬件看门狗，代理越界时在毫秒级隔离它。

但把这套东西拆开看，会看到一个很干净的结构：免费的软件层，专有的硬件层。 OpenShell 是 Apache 2.0、可在 Arm 与 Intel 平台上扩展；Sentry 是参考系统设计（reference system design），英伟达未公布其 license，且其策略执行建立在 DOCA 之上——只有装了英伟达 DPU 的机器才有「独立硅片上的强制」。所以这不是一次安全产品发布，这是一次收费口的迁移：把标准免费送出去，把收费站修在「通往模型的唯一路径」上。

三个判据，全部指向同一个结论：① 开源协议覆盖到哪一层为止——它止于软件，硬件那半没开源；② 宣传语是「让你不用慢下来」还是「我们必须慢下来」——黄仁勋选的是前者，这是把安全做成继续加速的许可证；③ 收费站是否建在必经之路上——在 Vera Rubin POD 里，每块计算托架都含一颗 BlueField-4，位置就在节点通往模型的唯一一条路径上。
对账户：这是控制面的争夺，不是性能的争夺；本组合没有安全标的，不因此调仓。

二、OpenShell：免费的软件层，把「代理能碰什么」变成可验证的策略

先把大白话说清楚。代理（agent）和聊天机器人的区别在于：它不只是回答，它能调用工具、读写文件、连网络、连续执行几天几周的任务。你给它目标，它自己找路径。危险就出在「自己找路径」这四个字上——为了完成任务，它会绕过你在应用层设的限制。

英伟达的切入点是一句很硬的话：提示词层面的护栏是一个请求（request），不是一个边界（boundary）。 所以它把边界挪到代理进程之外。OpenShell 0.1.0（Apache 2.0，已「广泛可用」，GitHub 可下载）用三个组件分工：

组件职责关键点
OpenShell Gateway管理大量沙箱的生命周期与策略面向「代理军团（fleets）」而非单个代理——这是与单机沙箱的根本区别
OpenShell Supervisor与每个沙箱配对，运行在代理工作负载之外，逐一校验出站请求是否合规强制点不在代理内部，代理绕不过去；可检查 HTTP / GraphQL / MCP 流量——同一个 API 上「允许读、阻断写」
OpenShell Sandbox用内核级控制限制可读改的文件与进程，且除经 Supervisor 外没有任何网络路径代理去开 shell、跑生成的代码、起子进程、委派子代理时，这些控制都持续生效

几个工程细节值得单独拎出来，因为它们决定了这套东西的可验证性：

  • 策略写成 YAML，编译为 OPA/Rego；决策记录进 OCSF（开放网络安全模式框架）审计轨迹。这意味着策略是可被第三方审阅的文本，不是黑盒配置。
  • 凭证从不进入沙箱：代理工作负载内部只拿到一个占位符凭证，真凭证只在被授权的端点上绑定；占位符被发到许可清单之外的地址，请求直接被拒。授权访问某服务 ≠ 把该服务的凭证交给别的服务。
  • 策略证明器（policy prover）用形式逻辑检查一条策略授予的权限是否越出操作者定义的边界，并能指出具体是哪个动作越界。这是「可证明」三个字第一次被写进运行时，而不只是写在合规报告里。
  • 代理不能自批权限：运行时若发现需要新权限，代理可以提出一个范围很窄的策略变更建议，但该建议默认挂起等人工审核，代理无法批准自己的申请。
  • 支持 Codex、Claude Code、Pi、Hermes 等框架；已有采用者包括 Cadence（芯片设计，ChipStack 自主 RTL 设计工程师）、Slack（按需代理平台）、Gecko Robotics（物理机器人代理治理）。

唯一一组可查的对抗实验数据（英伟达自测）：在长周期对抗实验中，被削减了防护的前沿代理花了长达 2 小时试图说服一个 AI 审核员授予它修改受保护 GitHub 仓库的权限。英伟达称这些测试中没有发生对受保护仓库的写入。

注意口径：这是厂商自测，样本、对手强度与测试条件均未公布。它的价值不在数字本身，而在于它承认了一件事——「在这种情形下的代理，不能被指望完整地自我治理」。这句写在英伟达自己的工程博客里，是整份材料里最诚实的一句。

三、Sentry：不开源的那一半，站在通往模型的唯一路径上

如果 OpenShell 只是「又一个沙箱」，那它不值得单独写一份报告。真正让结构变得不一样的是 Sentry——因为它不解决隔离问题，它解决信任问题。

逻辑很直白：宿主（host）上的看门狗是可以被说服不看门的——宿主一旦被攻破，软件层的一切监控与强制都归零。所以 Sentry 把自己挪到另一块硅片上：

  • 跑在 BlueField-4 DPU 上，作为带外（out-of-band）看门狗，处于一个独立的信任域，用自己的 CPU、操作系统与安全服务——业界把它形容成「安全孤岛（safety island）」。
  • 每个 OpenShell 沙箱通过一个虚拟网卡绑定到 BlueField-4；OpenShell 的策略被复制到 DOCA 策略引擎上，在 L3 / L4 / L7 独立执行。即使跑代理的宿主被完全攻破，策略依然生效，因为它在另一块硅片上求值。
  • 基于 DOCA：检查代理的请求与响应、提供可信遥测（attested telemetry）、验证代理身份、对数据/工具/API/服务执行细粒度零信任策略。
  • 代理越界时毫秒级隔离并停止。

然后是那条最关键的位置信息：在 Vera Rubin POD 架构里，每一块计算托架都包含一颗 BlueField-4，位置就在这个节点通往模型的唯一一条路径上。英伟达工程博客把这层意思说得非常直接：

「通往模型的路径（the path to the model）就是控制点。代理没有下一次思考就无法行动。控制了通往模型的路径，你就同时拥有了最好的观察点和在需要时打断它的 kill switch。」

——英伟达开发博客（2026-09-28）

四、Vera CPU 为什么存在：安全不能让路

这一节回答一个此前一直悬着的问题——英伟达为什么要做 CPU。P66 把它当成「七芯片五机架」里的一颗规格芯片看，今天它的存在理由出现了。

英伟达给出的推理链条是这样的：沙箱不是免费的。每一次策略校验都消耗时钟周期——起沙箱、克隆仓库、重建镜像、重扫、每次调用都求值策略。「如果安全让代理变慢，压力永远是把管控放松。」 这句话点出了整个代理安全工程的死穴：安全与速度在同一个预算里竞争，而预算不足时被牺牲的一定是安全。

所以 Vera 的卖点不是通用算力，而是让「沙箱化一切」从权衡变成默认：

规格说明
88 个自研 Olympus 核Arm 架构，为 AI 工厂设计，而非传统云租赁经济学的通用核
确定性空间多线程让「每核一个沙箱」的校验延迟变得可预测——安全是延迟敏感的，抖动本身就是漏洞
Arm CCA 机密计算宿主内存隔离；配合 DPU 侧的 Argus（宿主内存异常检测）构成两层
最高 1.8× 同代 x86 的单核持续性能（代理类负载）官方口径，未公布基准细节
沙箱性能比传统 CPU 基础设施快最高 80%官方口径；这句才是 Vera 的正确定位——它是代理控制面的 CPU，不是通用服务器的 CPU

这一节的投资含义比看上去大。如果「代理控制面」真的成为一个独立的负载类别，那么 CPU 需求的结构会变——从「服务器主机的通用计算」分出「每个代理一个沙箱」的强制校验负载，而这类负载对确定性、隔离、核数敏感，对峰值算力不敏感。这是英伟达给自己新造的一个 TAM，而不是从 Intel/AMD 手里抢现有份额。同时它也是最容易证伪的一环：如果企业最终用纯软件方案（不要 DPU、不要专用 CPU）就把代理管住了，这一整层需求就不存在。

五、第一个收费站：开源的是软件，不开源的是硬件

把两份清单并排放，结构就浮出来了。

图 2 · 蓝色两层免费开放，琥珀三层不开源——开源协议止于软件，价值捕获止于硬件

这不是猜测，是公告本身写出来的：OpenShell 是 Apache 2.0，而 Sentry 被描述为「reference system design（参考系统设计）」，英伟达没有公布 Sentry 的 license，也没有公布「毫秒级」这一数字的测试条件。独立评论把这一点看得很清楚：

  • 混厂商车队的后果是具体的：带外强制只在装了英伟达 DPU 的机器上存在。用 Arm 或 Intel 主机的团队可以现在就用上 OpenShell 的沙箱与策略引擎，但 Sentry 是另一个决策——往服务器里放不放 BlueField-4。
  • 「可扩展至 Arm 与 Intel」是措辞，不是现成支持。在可测试的构建出现之前，这句话的真实含义是「移植工作归需要它的人」。
  • 反过来，已经跑在 Vera + BlueField-4 上的客户要启用这些保护，只需要一次软件更新。存量装机变成即时的安全供给——这是这次发布里最容易被低估的一句话。

于是第一个收费站的机制清楚了：免费的软件层负责抢标准——把策略格式、策略证明器、代理身份验证、密码学签名的「已验证代理技能」推广成事实接口；收费的硬件层负责收租——只有在它的 DPU 上才有硅片级的带外强制，只有在它的 CPU 上才有「沙箱化一切」的速度余量。

这里有一次旧条款的完美重演

体系里有一条老条款（灵魂第十三条）：「谁把『可证明安全』写进认证标准，买铲就从可选变必须。」 那一条原先是用来解释 AI 安全认证生意（P40）的。今天它换了载体：

英伟达做的不是「取得某个认证」，而是把「可证明」直接做进运行时——策略证明器用形式逻辑证明权限不越界；代理技能要经过目录登记、prompt injection / 工具投毒扫描、密码学签名并附带技能卡（skill card），让防御方能确认一个技能做什么、来自哪里、发布后有没有被改过。当「可证明安全」从纸面认证变成运行时接口，采购清单上的问题就从「你有没有过审」变成「你跑不跑在 OpenShell 上」——而跑在 OpenShell 上、又想要带外强制的人，最终会走到 BlueField-4 面前。

六、第二个收费站：安全是「继续加速」的许可证

这一节是整件事里最容易被当成公关辞令、但实际上是核心商业设计的一部分。

黄仁勋这几天在做一件很明确的事：把 AI 安全重新定义为工程问题，而不是「需要更多监管或全球协调」的问题。他与「AI 可能毁灭人类」的说法保持距离（报道里提到他与特朗普一道反驳了这类主张），同时坚持 AI 必须经过严格的安全测试。他的原话是：「AI 造福社会的巨大潜力，只有在解决了 AI 安全之后才能实现。在我们不断发现 AI 能力前沿的同时，必须加速发现 AI 安全的前沿。」

把这句话和同一周的另一件事放在一起，张力就出来了：

阵营安全怎么兑现副作用
暂停派（部分前沿实验室、安全研究者）靠减速兑现——OpenAI 已在 9/25 晚宣布暂停其最强模型的训练把时间表交给了说「必须慢下来」的一方；能力前沿的推进节奏变成安全议程的函数
工程派（英伟达）靠加锁兑现——把边界做进运行时与硅片，能力继续提速拿到了「不必减速也能安全」的话术权，并把这句话做成了可售卖的基础设施

这不是站队问题，是定价权问题。当整个行业面临「继续加速」与「必须减速」的政治压力时，谁提供「你不需要慢下来」的方案，谁就同时满足了两种需求——要速度的人要它，要安全的人也要它。反过来，只能靠「暂停」来兑现安全的一方，等于把自己的时间表交给了别人。

这条判据是可以套用到别处去的，不只英伟达。任何时候听到一个安全方案，先问它的宣传语是哪一种：「让你不用慢下来」，还是「我们必须慢下来」。前者在卖基础设施，后者在卖道德主张——而后者通常收不到钱。

七、谁受益、谁被收编：一张生态名单的读法

英伟达说已有 100 家以上机构参与（另一处口径为 120+，那是指 Open Secure AI Alliance 的成员数，两个名单不要混为一谈）。但这张名单不是平的——看它分几层，比看它有多长重要。

治理载体：一个还没长出牙齿的框架

平台挂着 Linux 基金会治理的 Open Secure AI Alliance，以及 SAFE（Shared AI Findings Exchange）框架。SAFE 设计了一套带截止时间的通知阶梯——受了影响尽快告知、有可证明暴露的客户72 小时内通知、4 个工作日内提交保密初步报告、30 天内发布初步公开报告与失效点分析；成员还必须报告「险兆事件（near misses）」而不只是已发生的损害。这套设计借鉴的是航空与金融业的事故共享惯例。

但要按公告成色给这件事定级。按体系老办法（灵魂第三十三条，公告成色分五级：①新闻稿 → ②产品化 → ③具名 → ④订单 → ⑤财报）：SAFE 停留在第①级——它目前只是一个 RFC，没有实施时间表，也没有提交初步报告的机制，可用的只有一个收反馈的 GitHub 仓库和工作组章程。OpenShell 到了②–③级（产品化 + 具名采用者）。Sentry 到了③级（具名，但未到订单与财报）。

另一个容易读错的地方：OpenAI 与 Anthropic 都不在 Open Secure AI Alliance 内（据 MSSP Alert 引 SDx Central）。这与「Anthropic 是平台生态伙伴」并不矛盾——联盟名单与平台生态是两套名单，把它们混着读会得出错误的分布判断。

八、第三个收费站：安全五家从「卖产品」变成「被调用」

这是本报告对旧结论最需要修正的一节。P40 当时把 AI 安全做成五家并行的候选（CHKP / FFIV / CSCO / PANW / FTNT），判断依据是「验证型公司里挑低估」。今天的公告没有推翻五家，但加进来一个基础设施级的裁判变量。

该怎么读？先说市场共识容易搞错的地方：这不是「英伟达颠覆安全厂商」。五家里有两家是平台方的贡献者，CrowdStrike 甚至把四个执行点嵌进了 OpenShell 运行时。分析师端的提醒也很一致——不要因为这条发布就做空 CRWD / PANW：它们拿到了分发与遥测机会，而且硬件看门狗替代不了三件事：跨云策略、事件响应、合规证据。

但反过来说，被收编和卖产品不是同一种生意。按体系里管收费口的那条老规矩（灵魂第四十七条）：收费口要按计费方式找，不按名字找。 那么问题是具体的：

  • 当「执行点」变成别人运行时里的一个插件，安全厂商是按订阅被卖，还是按被调用次数被结算？后者意味着收入跟着别人的平台走。
  • 当代理的默认边界由 OpenShell 免费提供，原先按「代理监控 / 工作负载安全 / 端点护栏」计费的那部分支出会被基础设施原生能力吃掉一块——分析师把它描述为「商品化部分端点、工作负载安全与代理监控支出」。
  • 真正替代不了的是责任与证据：出了事谁签字、给监管看什么、跨云归谁管。这三件事恰好是硬件看门狗覆盖不到的。

落到 CHKP 上，要说清楚一件事：今天该改的不是数字，是逻辑。P40 给 CHKP 的 Z1 118–125 / Z2 100–108 / Z3 85–92 与证伪线 75 是价格阶梯，而今天改变的是采购标准的形状——企业问的问题可能从「你有没有通过某项认证」变成「你跑不跑在 OpenShell 上、你的执行点在哪一层」。这是「有日历的账单」向「没日历的结构」的转换。按体系里 52 周低位那套判据（灵魂第四十八条）：有日历的等价格，没日历的等结构。 CHKP 现在属于后者——不动价格阶梯，但把它从「等价格」移到「等结构」的观察位上。

十三、体系位置

  • 灵魂第十三条（把「可证明安全」写进标准 ⇒ 买铲从可选变必须）：载体从「认证标准」换成「运行时标准」。策略证明器 + 密码学签名的已验证技能，就是新的「认证」。
  • 灵魂第十五条（卡点与永续租金）：卡点形态从芯片延伸到网络拓扑。
  • 灵魂第三十三条（公告成色五级）：本报告用给这件事定级——SAFE ①级、OpenShell ②–③级、Sentry ③级。「定级」本身就是纪律：不把新闻稿读成订单。
  • 灵魂第三十八条（开关分布决定确定性）：Sentry 让 kill switch 集中到一家芯片厂商手上。企业拿「行为可预测」换「依赖不可分散」——这个交换的定价还没出现。
  • 灵魂第四十七条（收费口按计费方式找）：安全厂商的位置从「卖产品」变成「被调用的一环」，其计费方式是否随之改变，是这一层最重要的观察点。
  • 灵魂第四十八条（有日历的等价格，没日历的等结构）：CHKP 今天从前者移到后者。
  • 灵魂第五十一 / 五十三条（P59 / P61）：今天同时被兑现——责任缺口上建起了收费站，指令真实性验证下沉到了硅层。
  • 灵魂第六十五条（P66：卖铲人因「买铲」涨价而下调毛利率时，涨价那环才是收租人）：今天补一句——卖铲人还可能是把「责任」本身做成了一把铲子。
体系灵魂第六十六条
开源的是软件，不开源的是硬件——当一家公司白送某一层时，先问它把收费站挪到了哪一层。
免费层的作用是抢标准：把接口、策略格式、协议推广成事实默认，让所有人都按你的写法描述问题。收费层的作用是收租：只有在它的硅片上才有那个「独立执行」的版本。判据很具体——开源协议覆盖到哪一层为止（OpenShell 是 Apache 2.0，Sentry 没有 license）。看到「开放平台」四个字，第一件事是把它的层次清单画出来，看那道分界线落在哪。
体系灵魂第六十七条
安全是「继续加速」的许可证，不是减速的刹车。
当整个行业同时承受「要速度」和「要安全」两种压力时，谁提供「不必慢下来也能安全」的方案，谁就同时满足两种需求——要速度的人买它，要安全的人也买它。反过来，只能靠「暂停」兑现安全的一方，等于把自己的时间表交给别人。判据是宣传语的方向：说的是「让你不用慢下来」，还是「我们必须慢下来」。前者在卖基础设施，后者在卖道德主张——后者通常收不到钱。这一条可以套到任何安全、合规、环保议题上，不限于 AI。
体系灵魂第六十八条
收租的位置在「必经之路」上，不在性能上。
站在必经之路上的人同时拿到两样东西：最好的观察点，和唯一的终止权。「控制了通往模型的路径，你就同时拥有最好的观察点和 kill switch」——这话出自卖方之口，但逻辑本身是硬的：观察点与终止权在同一个位置，是拓扑决定的事实，不是产品特性。所以判据不是「它的性能高多少」，而是「数据流是不是必须经过它」。而下一步要问的是灵魂第三十八条那个问题——这条路上一共几个开关持有人；只有一个时，你买到的「确定性」是多少钱，你让出的「依赖可分散性」又值多少钱。

五句话总结

  1. 这件事的本质不是安全产品，是收费口迁移。 OpenShell 免费开源抢标准，Sentry 不开源收租——分界线落在软件与硬件之间，这就是全部结构。
  2. 它把「责任」从成本项变成了硬件。 P59 只能指出「责任无人收费的那一层是下一个定价缺口」，今天这个缺口上出现了一个具体价目：一颗 DPU、一颗 CPU，位置在通往模型的唯一路径上。
  3. 「安全是加速的许可证」这门生意，比安全本身值钱。 黄仁勋要的不是监管豁免，是把「不必减速」做成可售卖的基础设施——这让他同时拿到要速度的人和要安全的人的预算。
  4. 对安全厂商是收编不是颠覆，但收编也是重新定价。 PANW / CSCO 成了平台贡献者，CRWD 把四个执行点嵌进了 OpenShell；不该据此做空它们，但该问一句：被调用的一环，按什么方式计费。
  5. 今天的证伪线只有一条，但很硬。 如果超大规模厂商用纯软件方案就把代理管住了，那么 Vera 与 BlueField 的新增需求不成立，整篇推导作废。在那之前，Sentry 没有 license、毫秒级没有第三方验证、Arm 与 Intel 只是「可以扩展」——这三条同时成立，说明真正卖出去的东西比宣传的小一圈。
